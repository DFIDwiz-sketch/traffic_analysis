What accounts for the large SMB connection?

The publisher’s Lumma exercise starts with a fingerprinting alert for traffic from 153.92.1.49:80. In the original capture, 10.1.21.58 sends HTTP traffic to that address. The same workstation also has a long-lived TCP/445 connection to domain controller 10.1.21.2 containing both an ordinary disk-share open attempt and a later burst of writes to named pipes. Identify the share, operation and destination object before interpreting the connection volume.

1 · Compare the internal SMB and external HTTP flows

Use the case tag in place of <CASE> and display the full capture range in UTC. Include the ingest interval if Splunk uses it for the time picker. Use Zeek ts for the timeline. The examples assume flattened fields.

SPL 
index=zeek pcap_case="<CASE>"
| stats count min(ts) as first max(ts) as last by sourcetype
| eval first=strftime(first,"%Y-%m-%d %H:%M:%S %Z"), last=strftime(last,"%Y-%m-%d %H:%M:%S %Z")
| sort - count

Check for the connection, SMB and DCE/RPC sourcetypes. An SMB capture can produce different logs depending on the analyzer and ingest configuration.

SPL 
index=zeek sourcetype=zeek:conn pcap_case="<CASE>" proto=tcp id_orig_h=10.1.21.58
    ((id_resp_h=10.1.21.2 id_resp_p=445) OR (id_resp_h=153.92.1.49 id_resp_p=80))
| sort 0 ts
| table ts uid id_resp_h id_resp_p id_orig_p duration orig_pkts resp_pkts orig_bytes resp_bytes

Compare client and server packet counts, bytes and duration for each connection. The original TCP/445 tuple with client port 50768 contains 21,997 captured packets in both directions. That is the tuple to inspect by tree. The external HTTP connection has a different UID for its network and application events.

1 · 내부 SMB 흐름과 외부 HTTP 흐름 비교하기

<CASE>에 사례 태그를 넣고 캡처 전체 구간을 UTC로 표시합니다. Splunk가 수집 시각으로 필터링하면 해당 구간을 포함합니다. 타임라인에는 Zeek ts를 사용합니다. 예시는 평탄화된 필드명을 사용합니다.

SPL 
index=zeek pcap_case="<CASE>"
| stats count min(ts) as first max(ts) as last by sourcetype
| eval first=strftime(first,"%Y-%m-%d %H:%M:%S %Z"), last=strftime(last,"%Y-%m-%d %H:%M:%S %Z")
| sort - count

연결, SMB, DCE/RPC 로그가 있는지 확인합니다. 분석기와 수집 설정에 따라 생성되는 SMB 로그 종류가 달라질 수 있습니다.

SPL 
index=zeek sourcetype=zeek:conn pcap_case="<CASE>" proto=tcp id_orig_h=10.1.21.58
    ((id_resp_h=10.1.21.2 id_resp_p=445) OR (id_resp_h=153.92.1.49 id_resp_p=80))
| sort 0 ts
| table ts uid id_resp_h id_resp_p id_orig_p duration orig_pkts resp_pkts orig_bytes resp_bytes

연결별로 클라이언트와 서버의 패킷·바이트 수, 연결 시간을 비교합니다. 원본에서 클라이언트 포트 50768을 사용한 TCP/445 연결의 양방향 패킷은 21,997개입니다. 이 연결을 SMB 트리별로 분석합니다. 외부 HTTP 연결에는 네트워크와 애플리케이션 기록을 연결할 자체 UID가 있습니다.

2 · Split the SMB connection by tree and object

SPL 
index=zeek pcap_case="<CASE>" uid="<SMB_UID>"
    sourcetype IN ("zeek:conn","zeek:smb_mapping","zeek:smb_files","zeek:dce_rpc")
| sort 0 ts
| table ts sourcetype uid path share_type name action named_pipe endpoint operation

Take the UID for SMB client port 50768. Correlate conn, SMB and DCE/RPC rows by uid within the same Zeek processing run. One UID can contain more than one tree. In packets, the two Tree Connect replies supply the tree IDs. For writes, match the SMB session, tree and handle from the file open. Use message ID within that session to pair the write request and response.

SPL 
index=zeek sourcetype=zeek:dce_rpc pcap_case="<CASE>" uid="<SMB_UID>"
| eval second=floor(ts), pipe=coalesce(named_pipe,"unknown"),
    rpc_endpoint=coalesce(endpoint,"unknown"), rpc_operation=coalesce(operation,"unknown")
| stats count as rpc_log_rows by second pipe rpc_endpoint rpc_operation
| sort 0 second - rpc_log_rows

Look for the DCE/RPC burst and compare operations and endpoint values. Individual rows can describe RPC operations, while packet counts include both directions and transport traffic. In the scoped PCAP analysis, 4,148 distinct SMB2 WRITE requests were identified on the IPC$ tree on this tuple in about three seconds. The count uses visible SMB2 request headers grouped by session, tree and message ID. It counts write requests, including RPC setup and data, and carries no assumption about the number of files or accounts involved.

2 · SMB 연결을 트리와 대상 객체로 나누기

SPL 
index=zeek pcap_case="<CASE>" uid="<SMB_UID>"
    sourcetype IN ("zeek:conn","zeek:smb_mapping","zeek:smb_files","zeek:dce_rpc")
| sort 0 ts
| table ts sourcetype uid path share_type name action named_pipe endpoint operation

SMB 클라이언트 포트 50768의 UID를 가져옵니다. 동일한 Zeek 처리 실행 내에서 uid로 연결, SMB, DCE/RPC 로그를 연계합니다. UID 하나에 여러 트리가 포함될 수 있습니다. 패킷에서는 두 Tree Connect 응답에서 트리 ID를 확인합니다. 파일 열기에서 확인한 SMB 세션, 트리, 핸들로 쓰기 대상을 찾고, 세션 내 메시지 ID로 요청과 응답을 연결합니다.

SPL 
index=zeek sourcetype=zeek:dce_rpc pcap_case="<CASE>" uid="<SMB_UID>"
| eval second=floor(ts), pipe=coalesce(named_pipe,"unknown"),
    rpc_endpoint=coalesce(endpoint,"unknown"), rpc_operation=coalesce(operation,"unknown")
| stats count as rpc_log_rows by second pipe rpc_endpoint rpc_operation
| sort 0 second - rpc_log_rows

DCE/RPC 요청이 집중된 구간의 작업과 엔드포인트를 비교합니다. Zeek의 행은 RPC 작업을 나타낼 수 있고, 패킷 수에는 양방향 데이터와 전송 제어 트래픽도 포함됩니다. 원본에서 이 연결의 IPC$ 트리에 약 3초 동안 고유 SMB2 WRITE 요청 4,148건이 관찰됐습니다. 읽을 수 있는 SMB2 요청 헤더를 세션, 트리, 메시지 ID로 구분해 집계한 값입니다. RPC 설정과 데이터를 운반하는 쓰기도 포함되므로 파일 수나 계정 수로 해석할 수 없습니다.

요청 급증으로 계정이나 정책 정보를 조회했을 가능성을 조사할 수 있습니다. 승인된 자산 인벤토리와 디렉터리 조회에도 같은 파이프가 쓰입니다. 선택한 사례의 SMB 응답은 파이프로 데이터를 전달했음을 보여 줍니다. 실행 프로세스, RPC 결과, 앞선 HTTP와의 관계는 후속 조사에서 확인합니다.

3 · Verify the two SMB trees and the separate HTTP flow in Arkime

Arkime 
tags == "<CASE>" && ip.src == 10.1.21.58 && ip.dst == 10.1.21.2 && port.src == 50768 && port.dst == 445

In the first session, locate the Shared Tree Connect reply and the missing file result. Move to the IPC$ Tree Connect and inspect the following pipe open and write. Record the full tuple and packet times as well as original frame numbers, because exports can renumber them.

Arkime 
tags == "<CASE>" && ip.src == 10.1.21.58 && ip.dst == 153.92.1.49 && port.src == 54492 && port.dst == 80

Open the external HTTP session and verify the POST and response direction. Record this connection separately. Use endpoint process evidence to test whether the HTTP and RPC originated from one process.

3 · Arkime에서 두 SMB 트리와 별도 HTTP 흐름 확인하기

Arkime 
tags == "<CASE>" && ip.src == 10.1.21.58 && ip.dst == 10.1.21.2 && port.src == 50768 && port.dst == 445

첫 세션에서 Shared의 Tree Connect 응답과 파일을 찾지 못한 결과를 확인합니다. 이어서 IPC$ Tree Connect 뒤의 파이프 열기와 쓰기를 봅니다. 내보내면 프레임 번호가 바뀔 수 있으므로 전체 주소·포트와 패킷 시각도 기록합니다.

Arkime 
tags == "<CASE>" && ip.src == 10.1.21.58 && ip.dst == 153.92.1.49 && port.src == 54492 && port.dst == 80

외부 HTTP 세션을 열어 POST와 응답의 방향을 확인하고 별도 연결로 기록합니다. HTTP와 RPC가 같은 프로세스에서 발생했는지는 엔드포인트 근거로 확인합니다.

4 · Confirm the two tree IDs offline if needed

TShark 
tshark -2 -n -r "2026-01-31-traffic-analysis-exercise.pcap" \
  -Y 'frame.number == 424 || frame.number == 28294 || frame.number == 28303 || frame.number == 28304' \
  -T fields -E header=y -e frame.number -e tcp.stream -e ip.src \
  -e smb2.sesid -e smb2.tid -e smb2.msg_id -e smb2.cmd -e smb2.nt_status

If Arkime does not expose SMB2 tree identifiers clearly, inspect these four frames in the original capture. Compare tree IDs in the two Tree Connect replies, then match the samr write and reply by message ID and stream. Limit the output to protocol metadata.

4 · 필요할 때만 두 트리 ID를 오프라인으로 확인하기

TShark 
tshark -2 -n -r "2026-01-31-traffic-analysis-exercise.pcap" \
  -Y 'frame.number == 424 || frame.number == 28294 || frame.number == 28303 || frame.number == 28304' \

Arkime에서 SMB2 트리 ID가 분명하지 않으면 원본 네 프레임을 조회합니다. 두 Tree Connect 응답의 트리 ID를 비교하고 samr 쓰기와 회신은 같은 스트림의 메시지 ID로 짝짓습니다. 출력은 프로토콜 메타데이터로 제한합니다.

5 · Report the separate operations and corroborate discovery

Record the capture hash, host pair, connection tuple, tree IDs, write-request count and selected replies. Check the source host’s process telemetry and the DC’s directory and share auditing for the burst. Compare authorized inventory schedules and record whether any identity queries, changes or follow-on actions are independently supported.
