Which domain operations did the capture record?

The publisher’s “KongTuke Rebuke!” exercise uses traffic from an infected Windows workstation in a lab domain. In the original capture, 10.9.11.135 reads policy files over SMB2 from the DC at 10.9.11.2 and later exchanges data with samr and lsarpc named pipes. The same workstation also makes external HTTP requests. Track the file reads, pipe operations and outbound requests separately before assessing causation.

1 · Baseline the workstation-to-DC connections

Replace <CASE> with the import tag. Set Splunk to UTC and cover the capture range. If _time stores ingest time, widen the picker and use numeric Zeek ts for event time. The examples use flattened fields.

SPL 
index=zeek pcap_case="<CASE>"
| stats count min(ts) as first max(ts) as last by sourcetype
| eval first=strftime(first,"%Y-%m-%d %H:%M:%S %Z"), last=strftime(last,"%Y-%m-%d %H:%M:%S %Z")
| sort - count

Check whether connection, SMB share, file and RPC logs arrived. Confirm decoder coverage before interpreting absent logs.

SPL 
index=zeek sourcetype=zeek:conn pcap_case="<CASE>" id_orig_h=10.9.11.135
    id_resp_h=10.9.11.2 id_resp_p=445 proto=tcp
| sort 0 ts
| table ts uid id_orig_p duration conn_state orig_pkts resp_pkts missed_bytes

Compare the DC pair’s source ports, timestamps, packet counts and states. The original file has 626 packets in both directions for workstation-initiated TCP/445 to the DC, including ACKs and control traffic. Use the port column to locate 51139 for the later policy and pipe operations.

1단계 · 워크스테이션과 DC 간 연결 베이스라인 확인

<CASE>에 수집 태그를 넣고 Splunk 시간대를 UTC로 설정합니다. 전체 캡처 구간을 포함합니다. _time이 수집 시각이면 범위를 넓히고 사건 순서는 숫자형 Zeek ts로 읽습니다. 예제는 평탄화된 필드를 사용합니다.

SPL 
index=zeek pcap_case="<CASE>"
| stats count min(ts) as first max(ts) as last by sourcetype
| eval first=strftime(first,"%Y-%m-%d %H:%M:%S %Z"), last=strftime(last,"%Y-%m-%d %H:%M:%S %Z")
| sort - count

연결, SMB 공유·파일과 RPC 로그가 수집됐는지 확인합니다. 로그가 없는 부분은 분석기 적용 범위를 확인한 뒤 해석합니다.

SPL 
index=zeek sourcetype=zeek:conn pcap_case="<CASE>" id_orig_h=10.9.11.135
    id_resp_h=10.9.11.2 id_resp_p=445 proto=tcp
| sort 0 ts
| table ts uid id_orig_p duration conn_state orig_pkts resp_pkts missed_bytes

DC 방향 연결을 출발지 포트, 시각, 패킷 수와 상태로 비교합니다. 원본에서 워크스테이션이 시작한 DC 방향 TCP/445에는 제어와 ACK를 포함해 양방향 626개 패킷이 있었습니다. 후속 정책 및 파이프 작업을 확인할 때는 출발지 포트 51139로 좁힙니다.

2 · Verify share context and check the outbound overlap

SPL 
index=zeek pcap_case="<CASE>" uid="<SMB_UID>"
    sourcetype IN ("zeek:conn","zeek:smb_mapping","zeek:smb_files","zeek:dce_rpc")
| sort 0 ts
| table ts sourcetype uid id_orig_p path name action endpoint operation

Copy the UID for port 51139. Use it only with logs from the same Zeek processing run and select one ingest if the capture was imported twice. Compare share paths, file actions and any recorded RPC endpoint and operation. The connection UID can cover multiple tree connections. Match the active tree ID, open handle and direction in the packet view.

SPL 
index=zeek sourcetype=zeek:http pcap_case="<CASE>" id_orig_h=10.9.11.135
    id_resp_h=86.106.87.134 id_resp_p=80 method=POST
| sort 0 ts
| table ts uid id_orig_p http_host status_code request_body_len

Map the protocol Host to http_host separately from Splunk’s event host. The external HTTP flows have their own UIDs. Use each for its own connection record. Compare the SMB window with HTTP by workstation, time and endpoint process telemetry where available. The same responder IP can serve different HTTP Host values.

Standard Group Policy processing can account for policy reads. Authorized administration can open both pipes. The SMB write replies confirm acceptance at the pipe level. The caller, RPC effect, DC state changes and any link to the outbound traffic require corroboration.

2단계 · 공유 작업과 겹치는 외부 통신 확인

SPL 
index=zeek pcap_case="<CASE>" uid="<SMB_UID>"
    sourcetype IN ("zeek:conn","zeek:smb_mapping","zeek:smb_files","zeek:dce_rpc")
| sort 0 ts
| table ts sourcetype uid id_orig_p path name action endpoint operation

포트 51139의 UID를 가져와 같은 Zeek 처리 실행의 로그에서 사용합니다. 여러 번 가져온 캡처라면 한 실행을 고릅니다. 공유 경로, 파일 동작과 수집된 RPC 엔드포인트·작업을 비교합니다. 연결 UID 하나에 여러 공유 연결이 포함될 수 있습니다. 패킷에서 당시의 트리 ID, 열린 핸들과 방향을 확인합니다.

SPL 
index=zeek sourcetype=zeek:http pcap_case="<CASE>" id_orig_h=10.9.11.135
    id_resp_h=86.106.87.134 id_resp_p=80 method=POST
| sort 0 ts
| table ts uid id_orig_p http_host status_code request_body_len

프로토콜의 HTTP Host를 Splunk 이벤트 호스트와 별개인 http_host로 추출합니다. 외부 HTTP에는 연결별 UID가 있으므로 각각의 연결 기록과 대조합니다. SMB 구간과 HTTP는 워크스테이션, 시각 및 확보한 프로세스 네트워크 기록으로 비교합니다. 응답자 IP 하나에 서로 다른 HTTP Host가 나타날 수 있습니다.

정상 Group Policy 처리에서도 정책 파일을 읽습니다. 승인된 관리 작업도 두 파이프를 열 수 있습니다. SMB 쓰기 응답은 파이프 수준의 수락을 보여 줍니다. 호출 주체, RPC 작업의 결과, DC 상태 변경과 외부 트래픽과의 연결에는 추가 근거가 필요합니다.

3 · Cross-check the internal and outbound sessions in Arkime

Arkime 
tags == "<CASE>" && ip.src == 10.9.11.135 && ip.dst == 10.9.11.2 && port.src == 51139 && port.dst == 445

Use the case tag and review the policy reads and pipe exchanges on client port 51139. Match each pipe exchange to the assigned tree ID using the successful tree response.

Arkime 
tags == "<CASE>" && ip.src == 10.9.11.135 && ip.dst == 86.106.87.134 && port.dst == 80

Check the earlier and later outbound requests in separate sessions around the documented times. Compare their Host values and record the tuple and timestamp for each.

Arkime

케이스 태그와 출발지 포트 51139를 사용해 정책 읽기와 파이프 교환을 확인합니다. 성공한 트리 응답의 할당 ID를 각 파이프 작업과 대조합니다.

Arkime

기록한 시각에 이전과 이후 외부 요청을 각각 엽니다. Host 값을 비교하고 주소·포트와 시각을 남깁니다.

4 · Confirm the IPC tree IDs offline if needed

TShark 
tshark -n -r "2026-09-11-traffic-analysis-exercise.pcap" \
  -Y 'frame.number == 71957 || frame.number == 71958 || frame.number == 72033 || frame.number == 72034' \
  -T fields -E header=y -e frame.number -e frame.time_epoch -e ip.src -e tcp.stream \
  -e smb2.msg_id -e smb2.tid -e smb2.tree -e smb2.nt_status

If Arkime leaves the two IPC assignments ambiguous, read the four original frames. Pair requests and replies by stream, message ID and direction. Read the assigned ID and status from the DC reply.

4단계 · 필요하면 IPC 트리 ID만 오프라인에서 확인

TShark 
tshark -n -r "2026-09-11-traffic-analysis-exercise.pcap" \
  -Y 'frame.number == 71957 || frame.number == 71958 || frame.number == 72033 || frame.number == 72034' \
  -T fields -E header=y -e frame.number -e frame.time_epoch -e ip.src -e tcp.stream \
  -e smb2.msg_id -e smb2.tid -e smb2.tree -e smb2.nt_status

Arkime에서 두 IPC 연결의 할당 ID가 분명하지 않으면 원본 프레임 네 개를 읽습니다. TCP 스트림, 메시지 ID와 방향으로 요청과 응답을 연결하고, DC 응답에서 트리 ID와 상태를 확인합니다.

5 · Document observed access and investigate the caller

Record the hash, workstation and DC, confirmed share actions, pipe names and external timings. Ask for endpoint process-network events, DC share and directory logs and approved maintenance records. Use those sources before assigning an RPC operation to a process or judging whether state changed on the DC.

5단계 · 접근을 기록하고 호출 주체 확인

캡처 해시, 워크스테이션과 DC, 공유 작업, 파이프 이름과 외부 통신 시각을 남깁니다. 엔드포인트 프로세스 네트워크 기록, DC의 공유·디렉터리 로그와 승인된 유지보수 자료를 요청합니다. 해당 자료로 RPC를 호출한 프로세스와 DC에 실제 변경이 있었는지 확인합니다.
