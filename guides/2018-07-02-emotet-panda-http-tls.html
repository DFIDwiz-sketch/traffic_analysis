What protocol actually reached TCP/443?

The publisher describes a workstation infection with Emotet followed by Zeus Panda Banker. In the original capture, workstation 10.7.2.101 sends plaintext HTTP to one TCP/443 destination and later sends a TLS ClientHello to another TCP/443 destination. This guide checks what the network evidence says about each flow and what a SOC ticket still needs from the endpoint.

TCP/443에서 어떤 프로토콜이 관찰됐나

공개 원문은 워크스테이션에서 Emotet에 이어 Zeus Panda Banker가 관찰됐다고 보고합니다. 원본 캡처에서 10.7.2.101은 한 TCP/443 목적지에 평문 HTTP를 보냈고, 이후 다른 TCP/443 목적지로 TLS ClientHello를 보냈습니다. 각 연결을 네트워크 근거로 확인하고 SOC 티켓에 필요한 엔드포인트 후속 항목을 정리합니다.

악성코드 계열과 감염 순서는 공개 원문에 근거합니다. 아래 패킷 시각, 포트, HTTP 헤더 및 TLS 서버 이름은 원본 캡처에서 직접 확인했습니다. 검색은 실습 환경의 수집 결과에서 검증할 예제입니다.

1 · Baseline the workstation in Splunk

Use the case value assigned during import for <CASE>, set the display timezone to UTC, and include the full capture interval. Enlarge the time range if Splunk uses ingestion time for _time. Use the Zeek ts field to order the traffic. The examples assume flattened fields.

SPL 
index=zeek pcap_case="<CASE>"
| stats count min(ts) as first max(ts) as last by sourcetype
| eval first=strftime(first,"%Y-%m-%d %H:%M:%S %Z"), last=strftime(last,"%Y-%m-%d %H:%M:%S %Z")
| sort - count

Check for zeek:conn, zeek:http and TLS records, typically imported as zeek:ssl. Adjust the sourcetypes if your input uses different names.

SPL 
index=zeek sourcetype=zeek:conn pcap_case="<CASE>" id_orig_h=10.7.2.101 proto=tcp
| eval service_label=coalesce(mvjoin(service,","),"unidentified")
| stats count as connections dc(id_resp_h) as destinations values(conn_state) as states
    by id_resp_p service_label
| sort 0 - connections

Group the workstation’s TCP connections by responder port and Zeek service. A service label reflects protocol recognition. An unidentified entry is a cue to inspect its packets. Compare the port 443 rows and use responder IPs to narrow the two flows. The capture includes other activity from the lab host, so the baseline is scoped to this file.

1단계 · Splunk에서 워크스테이션 베이스라인 확인

<CASE>에 가져올 때 지정한 케이스 값을 넣고 표시 시간대를 UTC로 설정합니다. 전체 캡처 구간을 포함합니다. Splunk _time이 수집 시각이면 범위를 넓히고 트래픽 순서는 Zeek ts로 읽습니다. 예제는 평탄화된 필드를 기준으로 합니다.

SPL 
index=zeek pcap_case="<CASE>"
| stats count min(ts) as first max(ts) as last by sourcetype
| eval first=strftime(first,"%Y-%m-%d %H:%M:%S %Z"), last=strftime(last,"%Y-%m-%d %H:%M:%S %Z")
| sort - count

zeek:conn, zeek:http와 일반적으로 zeek:ssl로 수집하는 TLS 로그를 확인합니다. 수집 설정에 따라 sourcetype 이름을 조정합니다.

SPL 
index=zeek sourcetype=zeek:conn pcap_case="<CASE>" id_orig_h=10.7.2.101 proto=tcp
| eval service_label=coalesce(mvjoin(service,","),"unidentified")
| stats count as connections dc(id_resp_h) as destinations values(conn_state) as states
    by id_resp_p service_label
| sort 0 - connections

워크스테이션의 TCP 연결을 응답자 포트와 Zeek가 식별한 서비스별로 묶습니다. 서비스가 식별되지 않은 행은 원본 패킷을 확인합니다. 포트 443의 행을 비교한 뒤 응답자 IP를 기준으로 두 흐름을 좁힙니다. 다른 실습 트래픽도 함께 기록됐으므로 베이스라인은 이 캡처 파일의 범위로 해석합니다.

2 · Verify HTTP and TLS before assigning meaning

SPL 
index=zeek pcap_case="<CASE>" id_orig_h=10.7.2.101 id_resp_p=443
    id_resp_h IN ("24.173.127.246","185.45.193.240")
    sourcetype IN ("zeek:conn","zeek:http","zeek:ssl")
| sort 0 ts
| table ts sourcetype uid id_orig_p id_resp_h service trans_depth method status_code server_name established

Read the connection row first, then compare method and status_code from HTTP with server_name and established from TLS where those fields exist. Use each connection’s uid with its application records from the same Zeek processing run. If the capture was imported twice, isolate one run. Use client IP and time to compare flows with different UIDs.

UTC · 2 July Original frames Directly observed
14:38:24.663–14:38:24.817 975, 977 HTTP GET to 94.141.21.54:80, followed by HTTP 200 with declared application/octet-stream
14:38:53.085–14:38:53.770 1231, 1233 Plaintext HTTP POST and 200 response on 24.173.127.246:443, client port 49205
14:42:01.243 1786 TLS ClientHello to 185.45.193.240:443, client port 49207, with SNI canariasmotor.top

A nonstandard plaintext HTTP service, a proxy or test software can account for some traffic on port 443. SNI identifies the server name requested in the TLS handshake. It leaves the encrypted contents and process ownership unresolved. Likewise, a declared binary content type does not establish file identity or execution.

2단계 · HTTP와 TLS를 확인한 뒤 해석

SPL 
index=zeek pcap_case="<CASE>" id_orig_h=10.7.2.101 id_resp_p=443
    id_resp_h IN ("24.173.127.246","185.45.193.240")
    sourcetype IN ("zeek:conn","zeek:http","zeek:ssl")
| sort 0 ts
| table ts sourcetype uid id_orig_p id_resp_h service trans_depth method status_code server_name established

연결 행을 먼저 읽고 HTTP의 method와 status_code, TLS의 server_name과 established를 수집된 범위에서 비교합니다. 연결의 uid로 같은 Zeek 처리 실행의 응용 계층 기록을 찾습니다. 캡처를 두 번 가져왔다면 한 실행으로 제한합니다. UID가 다른 흐름을 비교할 때는 클라이언트 IP와 시각을 사용합니다.

7월 2일 UTC 원본 프레임 직접 확인한 근거
14:38:24.663–14:38:24.817 975, 977 94.141.21.54:80으로 HTTP GET, 이후 application/octet-stream을 선언한 HTTP 200 응답
14:38:53.085–14:38:53.770 1231, 1233 24.173.127.246:443의 평문 HTTP POST와 200 응답, 출발지 포트 49205
14:42:01.243 1786 185.45.193.240:443으로 보낸 TLS ClientHello, 출발지 포트 49207, SNI는 canariasmotor.top

비표준 평문 HTTP 서비스, 프록시나 테스트 프로그램도 포트 443을 사용할 수 있습니다. SNI는 TLS 핸드셰이크에서 요청한 서버 이름입니다. 암호화된 내용이나 요청 프로세스에는 별도 근거가 필요합니다. 서버가 선언한 바이너리 콘텐츠 유형으로는 파일의 정체나 실행 여부를 확인할 수 없습니다.

4 · Compare just the protocol metadata offline if needed

TShark 
tshark -n -r "2018-07-02-Emotet-infection-with-Zeus-Panda-Banker.pcap" \
  -Y '(frame.number == 1231 || frame.number == 1233 || frame.number == 1786)' \
  -T fields -E header=y -e frame.number -e frame.time_epoch -e tcp.dstport \
  -e http.request.method -e http.response.code -e tls.handshake.type -e tls.handshake.extensions_server_name

If Arkime leaves protocol labels uncertain, compare these three frames in the original capture. HTTP method and response code should belong to the first flow, while handshake type and SNI belong to the second. A blank field can reflect decoder selection on a nonstandard port. Check the original packet view and TCP tuple before interpreting it.

4단계 · 필요한 경우 오프라인에서 프로토콜 메타데이터만 비교

TShark 
tshark -n -r "2018-07-02-Emotet-infection-with-Zeus-Panda-Banker.pcap" \
  -Y '(frame.number == 1231 || frame.number == 1233 || frame.number == 1786)' \
  -T fields -E header=y -e frame.number -e frame.time_epoch -e tcp.dstport \
  -e http.request.method -e http.response.code -e tls.handshake.type -e tls.handshake.extensions_server_name

Arkime에서 프로토콜이 분명하지 않으면 원본 프레임 세 개를 대조합니다. HTTP 메서드와 상태는 첫 흐름에, 핸드셰이크 유형과 SNI는 두 번째 흐름에 해당합니다. 비표준 포트의 분석기 선택 때문에 필드가 비어 있을 수 있으므로 원본 패킷과 연결 주소·포트를 함께 확인합니다.

5 · Record the flows and ask for endpoint confirmation

Record the workstation, PCAP hash, three destinations, protocol evidence, time range and original frame numbers. Check for an authorized client or proxy that could account for unusual port use. Request process-network telemetry and file-creation or execution events. Keep family attribution tied to the publisher until endpoint or file evidence supports it in the incident under review.

5단계 · 두 흐름을 기록하고 엔드포인트 확인 요청

워크스테이션, PCAP 해시, 목적지 세 곳, 프로토콜 근거, 시각과 원본 프레임 번호를 기록합니다. 승인된 클라이언트나 프록시가 특이한 포트 사용을 설명하는지 확인합니다. 프로세스 네트워크 로그와 파일 생성·실행 이벤트를 요청합니다. 조사 중인 사건에서 별도 엔드포인트나 파일 근거가 확인되기 전까지 악성코드 계열 식별은 공개 원문에 근거한 것으로 표시합니다.
